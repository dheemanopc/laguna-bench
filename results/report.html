Laguna Bench

Can Poolside's open-weights Laguna S 2.1, self-hosted on one AWS g7e.12xlarge, replace Sonnet as the executor under an Opus 5.5 planner inside Claude Code? Six real tasks mined from Memsys history, hidden tests, blind design review, Haiku and Sonnet as controls.

Model: Laguna S 2.1 FP8 · vLLM 0.25.1 · TP2Box: g7e.12xlarge (2× RTX PRO 6000 96 GB), us-east-1Master: Opus 5.525 scored runs
Decision under the plan's rule: Reject as a drop-in executor

Laguna does good work when it is reviewed, but it does not yet meet the bar against Sonnet.

  • Pass rate. On the five tasks Sonnet also ran, Laguna passed 4 of 11 valid runs (36%) vs Sonnet's 4 of 5 (80%). The rule needs ≥ 80% of Sonnet's rate; Laguna reached 45%.
  • Mandatory tasks. T3 passed 2 of 2. T1 failed 2 of 2 (32/35 and 27/35), while Sonnet passed T1 in 9 minutes, so T1 was solvable.
  • Design. Blind review averaged 4.0 for Laguna (9 runs, one contaminated run excluded) vs 5 for Sonnet's single T4 run. No test tampering by anyone.
  • Where it broke. Five of the seven failing runs hit the 120-minute cap, two of them before Opus reviewed anything. Every Laguna run that finished inside the cap passed, apart from the planner's own spec error on T4.

Serving Laguna on one g7e.12xlarge

Memory

  • FP8 weights 62 GiB per GPU; KV cache 1,478,805 tokens at 327k max length.
  • Hybrid sliding-window allocation works: about 12 KB per token per GPU, full-attention layers only.
  • With --max-model-len 1048576: 1,557,823 tokens, so a 1M context fits.

Latency

  • 300k prompt: 38 s cold, 0.79 s warm (prefix cached).
  • 892k prompt: 245 s cold, 2.1 s warm.
  • 128k parked agent evicted from GPU: 10.6 s to resume; with 300 GiB RAM KV offload 1.45 s, and GPU KV unchanged.

What we learned about the harness

  1. Prefix caching needs a shim. Claude Code sends system messages mid-conversation; vLLM folds them into the top system prompt, so the cache hit rate was 4%. A small gateway rewrites them in place: 98%.
  2. Use vLLM's own Anthropic endpoint. It returns signed thinking blocks; LiteLLM drops the signatures.
  3. Remote Control needs interactive sessions. claude -p --remote-control never registers; executors with a dummy auth token cannot attach at all.
  4. Deny plan-mode and worktree tools to executors. Laguna used both; one run waited 15 minutes at an approval dialog.
  5. Executor timeouts must cover the whole run budget, and a capped master must reap its executor. Six orphaned executors kept running for hours before this was caught.
  6. The executor allowlist was too literal. python3 -m pytest, cat and rm were denied; one Laguna run wrote 158 tests without ever running one.
  7. Over a mobile hotspot, compress the tunnel. Requests are 300–480 KB of JSON; SSH compression cut them 3× and took median first-token time from 27 s to 2 s during a congested hour.

Recommended next tests

  • Re-run Laguna with a checkpoint rule (report every 30 minutes or per work unit) and the wider allowlist. This targets the five capped, unreviewed failures directly.
  • Laguna tree under Opus with an abstract brief. Frontier writes the business spec; a Laguna DA designs and splits it; Laguna developers build; a Laguna reviewer checks technically against the spec. The solo run suggests the reviewer stage is what matters.
  • Scheduling gateway. Admission control at 5–7 decoding agents with adaptive limits, priorities by role, and RAM offload for parked agents, measured by replaying the recorded agent traffic.
  • NVFP4 on one GPU (g7e.4xlarge) for quality and throughput at about half the box cost.

Caveats

  • Small samples: 1–3 runs per task per executor; Sonnet ran each task once.
  • Laguna shared one GPU with 3–5 agents and ran over a mobile hotspot that degraded for about 30 minutes; affected runs were rerun or flagged.
  • All Laguna runs used FP8. The NVFP4 single-GPU configuration was not quality-tested.
  • Blind-review diffs for capped runs may include edits made by orphaned executors after scoring; official scores were taken at the cap.
  • Results reflect one Python codebase and its conventions.
