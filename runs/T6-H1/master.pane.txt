  Bugs found (each pinned with a strict xfail):
  1. Pagination is broken. Following any next_cursor raises asyncpg DataError, because the cursor's ISO timestamp is passed as a string where Postgres expects a timestamp. Pinned by the full-walk tests
     (test_full_walk_desc, _asc, _updated_at, _ties_desc, and test_basic_pagination_walk).
  2. Pagination would also skip a row per page. next_cursor points at the first row not returned, and the next page excludes that row. Crash 1 hides this; it is named in the same xfail reasons.
  3. Ties on created_at would be mishandled in descending order. The sort uses id ascending but the cursor comparison assumes id descending. Also hidden by crash 1; covered by test_full_walk_ties_desc.
  4. Some malformed cursors don't return -32602. Cursors that decode to {} raise KeyError, and 5 or null raise TypeError. Pinned by test_invalid_cursor_rejected[dict|int|null] and test_decode_cursor_json_dict.
  5. Cursors with a bad UUID or bad timestamp aren't validated. They reach the database and fail with DataError instead of -32602 (test_invalid_cursor_rejected[bad_uuid|bad_ts]).
  6. Notice payloads are stored as a JSON string, not an object. On a pool with the jsonb codec (the production pool and the test pool), jsonb_typeof(payload) comes out string. Delivery still works because it re-parses
     the string. Pinned by test_queue_payload_jsonb_type and test_queue_datetime_uuid_date_serialization.
  7. deliver_pending isn't reliably oldest-first. The sort is only inside the subquery, and the rows come back in storage order. Pinned by test_oldest_first_with_reverse_insertion, which forces a particular query plan so
