● My verdict on WP1 is REVISE, written to ~/laguna-bench/runs/F2-3/orders/review-wp1-1.md. The harness gates pass (ruff, mypy, no new test failures), but large parts of the planned scope are missing.

  1. Custom workflows still don't work. Status values are still checked against the old hard-coded list before the workflow check runs, so any status a team defines is rejected (work_items.py:257). The old transition
     table is also still in the code, though the plan says to remove it as the source of truth.
  2. New items aren't tied to a workflow version. Creating a work item doesn't record its workflow version and still starts it as todo, without checking the workflow's allowed starting statuses. WP0 deferred making that
     column required to WP1, and WP1 doesn't do it either. So "items never lose their history when the workflow changes" doesn't hold for new items.
  3. Teammates in other tenants still can't see or move each other's items. The item lookup for moves still filters by tenant (work_items.py:375). Listing, get and history aren't team-wide and don't return the allowed
     moves or sign-off state. The planned cross-tenant listing test wasn't added.
  4. Sign-off behaves differently from the design:
     - A second request on an item quietly reuses the open one instead of raising an error.
     - A request that reaches quorum is stored as "superseded" instead of "approved".
     - A move that completes after sign-off is always logged as coming from MCP, even when the web app made it.
     - The approval path locks only the request row, not the work item row.
  5. Five planned tests are missing:
     - inactive approver
     - two pending requests on one item
     - approval racing a move
     - seeding the default workflow twice adds only one
     - the two additions to the existing work-item service tests

     The rebase function is also named rebase_workitem instead of the planned rebase_work_item.
