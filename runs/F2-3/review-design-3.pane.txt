● I've sent the design back for revision; the review is in orders/review-design-3.md. The design fixes all five points from round 2, but it now has a blocking access-control problem.

  1. Team members would be locked out (blocking). The access rule the design uses on every new table reads team membership from the old team_members table. Nothing writes to that table any more, so it is empty for teams
     created now. Their members would be denied all reads and writes, including the step that seeds a default workflow for a new team. The design should use the current membership check from migration 0035, and test it
     with a team created through create_team.
  2. Rebase would fail on insert. A rebase writes a workflow_changed history row, but the design's change to the database check doesn't allow that value.
  3. Approver check uses the wrong function. During the sign-off count, the function used to decide whether an approver is still an active team member only works for the logged-in caller. It can't check anyone else.
  4. Permissions don't match what the code does. There's no insert permission on the table holding each team's current workflow, so seeding it would fail. The table of saved workflow versions is supposed to be
     unchangeable but would get update permission.
  5. Nit (not blocking): "Waiting on me" would match almost every item assigned to you in the default workflow. It should be narrowed or limited to sign-offs.
