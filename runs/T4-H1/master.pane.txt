  What was built:
  - Branch status (A): a new migration, alembic/versions/0044_2026_10_15_mindmap_branch_status.py, adds to each map node:
    - a stored status: open by default, or resolved / dropped;
    - the settlement details: one-line summary (≤500 chars), the resolving node, which party settled it, and when.

    CHECK constraints limit the allowed values and keep "open" and "settled" rows consistent. A downgrade followed by an upgrade runs cleanly.
  - mindmap_resolve (B): the new tool settles one branch in a single transaction:
    a. Locks the map and refuses an archived one (map_not_live).
    b. Checks the node belongs to this map. A node from another map, a random id or a deleted node all return the same -32602 error, so the tool can't be used to probe which ids exist.
    c. Refuses to settle the map's root node (closing the whole map is mindmap_close).
    d. Records the status, writes the resolves-under / dropped-under edge through the same insert_reference helper mindmap_link uses (only when a resolving node is named), and logs a resolve event.

    It returns the new cursor. Status is never inferred from edges. The tool is registered in main.py and has a description in tool_descriptions.py.
  - open_loops (C): now lists open nodes whose responsible_party is owner or model. Settled branches never appear.
  - Cheap reads (D): mindmap_get takes since, include and depth, all defaulting to the cheap setting, and returns a cursor, a resolved list, and status / truncated on each node. All existing output fields are kept.
